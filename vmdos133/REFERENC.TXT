【vm_alloc】        メモリブロック（Variable: 可変サイズ）の確保
---------------------------------------------------------------------
    構文: hand = vm_alloc( size );

    引数: WORD       size;  要求するメモリブロックのサイズ(byte)

    戻値: VMHAND     hand;  !=VM_NULL: ハンドル(32bit)
                            ==VM_NULL: ヒープメモリ不足

    処理: 指定されたサイズのメモリブロックを仮想メモリに確保し、その
          ハンドルを返します。
          確保されたメモリブロックは、０クリアされていません。
　　　　　ただし、デバッグモードでは常に０クリアされます。


=====================================================================
【vm_allocFix】     メモリブロック（Fixed: 固定サイズ）の確保
---------------------------------------------------------------------
    構文: hand = vm_allocFix( size );

    引数: WORD       size;  要求するメモリブロックのサイズ(byte)

    戻値: VMHAND     hand;  !=VM_NULL: ハンドル(32bit)
                            ==VM_NULL: ヒープメモリ不足

    処理: 指定されたサイズのメモリブロックを仮想メモリに確保し、その
          ハンドルを返します。
          確保されたメモリブロックは、０クリアされていません。
　　　　　ただし、デバッグモードでは常に０クリアされます。

          １ページを特定サイズ専用に割り当てることにより高速処理を実
          現しています。

    備考: 特定のサイズを頻繁にアロケートする場合にお使い下さい。
          _vFunc比、約５０～９０％の速度向上が期待できます。

【vm_check】        各種の診断をします
---------------------------------------------------------------------
    構文: iRet = vm_check( mode );

    引数: int        mode;  =0: 現在、ヒープメモリ上に存在するページ
                                に関して診断します。
                            =1: すべてのページについて診断します。
                                大量のページ移動が発生し、処理時間を要
                                するする場合があります。
                            =2: メモリリークについて診断します。
                                すべてのメモリブロックが解放されている
                                かを確認できます。

    戻値: int        iRet;  ==0: OK
                            !=0: ERROR
                                 エラーメッセージが、stderrへ出力されます。

    処理: mode=0,1: 各ページ内のヘッダとすべてのメモリブロックに付加さ
          れたチェックコードを調べます。
          オーバーライトしていそうな、行の直後に挿入すれば、バグの早
          期発見が可能です。 大抵の場合、mode=0 で十分です。
          mode=2: ページが存在するかをチェックします。

    備考: デバッグモード /D_AP_DEBUG の時だけ有効になります。
          リリースモードでの負荷はありません。

【vm_free】         メモリブロックの解放
---------------------------------------------------------------------
    構文: vm_free( hand );

    引数: VMHAND     hand;  ハンドル

    戻値: void

    処理: ハンドルにより示されるメモリブロックを仮想メモリから解放し

【vm_init】         ＶＭＭの初期化
---------------------------------------------------------------------
    構文: iRet = vm_init( wMin, wMax, wSwap, cPSize, errFunc );

    引数: WORD       wMin;  ヒープ必要最少容量
                            パラグラフ（16byte）単位です
          WORD       wMax;  ヒープ使用許可最大容量
                            パラグラフ（16byte）単位です
                            [ VM_ALLDOS ] 使用可能なヒープすべて利用します
          WORD      wSwap;  補助メモリ指定 [ VM_XMS|VM_EMS|VM_DISK ]
                            [ VM_ALLSWAP ] =(VM_XMS|VM_EMS|VM_DISK);
          char     cPSize;  ページサイズ
                            [ 1,2,4,8,16 ](KByte)のいずれか
          int  (*errFunc)(int, char*);
                            エラー発生時に呼び出される関数へのポインタ
                            =NULL: 内部エラールーチンに任せる

    戻値: int        iRet;  ==0: OK
                            !=0: ERROR

    処理: ＶＭＭの使用準備をします。

    備考: ページサイズは２がお薦めです。
          アプリケーションに最適なページサイズを探って下さい。

    備考: errFuncをセットすることにより、エラー発生時の処理ができます。
          また、vm_alloc,allocFix,reallocの戻値をチェックする必要がなく
          なります。
          つまり、errFuncが呼び出されない限り、正しいハンドルが返えさ
          れていると考えられます。
          o errFunc()の例は、サンプルリスト "vm_mix.c" などをご参照下さい。
          o errFunc()の第１引数として与えられるエラー番号は以下のとおりです。
              継続可能なエラー --> return(?);
                 0: Out of memory.
                 1: 警告
                 2: Memory CHECK 警告
              致命的エラー --> exit(-1);
                50: 致命的エラー
                51: 引数エラー
                52: Memory CHECK エラー
                53: 初期化されていません
          o デバッグモードのときは、errFunc()の第２引数として、
          　詳細なメッセージが与えられます。

    注意: 最初に必ず呼び出して下さい。

【vm_load】         メモリブロックのロード
---------------------------------------------------------------------
    構文: mem = vm_load( hand, flag );

    引数: VMHAND     hand;  ハンドル
          int        flag;  [ VM_CLEAN ] 移動時、破棄する
                              読み込みだけの為にロードする場合
                            [ VM_DIRTY ] 移動時、保存する
                              書き込みの為にロードする場合

    戻値: void       *mem;  !=NULL: ヒープメモリ・ポインタ
                            ==NULL: ヒープメモリ不足

    処理: 次に、どれかの vm_関数を呼び出す迄の間、メモリブロックを
          ロックし、そのヒープメモリ・ポインタを返します。

    備考: ロックされていないメモリブロックは適時、ＶＭＭにより移動さ
          れます。
          　VM_DIRTY フラグがセットされたメモリブロックは移動時に、仮
          想メモリへ保存されます。
            VM_CLEAN フラグでは、保存しないので高速です。

    注意: メモリブロックへ何等かの書き込みをするならば、[ VM_DIRTY ]
          を指示して下さい。


=====================================================================
【vm_lock】         メモリブロックのロック
---------------------------------------------------------------------
    構文: mem = vm_lock( hand );

    引数: VMHAND     hand;  ハンドル

    戻値: void       *mem;  !=NULL: ヒープメモリ・ポインタ
                            ==NULL: ヒープメモリ不足

    処理: 次に、vm_unlock または vm_unlockAll を呼び出す迄の間、メモ
          リブロックをロックし、そのヒープメモリ・ポインタを返します。

    備考: 一度にロック可能なメモリブロック数は、ヒープメモリ空き容量と
          ページサイズにより制限されます。

    注意: 同時に多数のロックをすると、簡単に「ヒープメモリ不足」になり
          ます。
          最小限のロック（リソースの独占）を心掛けて下さい。

【vm_realloc】      メモリブロックのサイズ変更
---------------------------------------------------------------------
    構文: hNew = vm_realloc( hOld, size );

    引数: VMHAND     hOld;  ハンドル   ロック中のハンドルは使えません
          WORD       size;  >0: 新たなメモリブロックのサイズ(byte)

    戻値: VMHAND     hNew;  !=VM_NULL: 変更後のハンドル(32bit)
                                       hOld は、無効です。
                            ==VM_NULL: エラー
                                       hOld は、有効です。

    処理: hOldで示されるメモリブロックを、新たなサイズで確保されたメモ
          リブロックへ移動し、hOldを破棄します。
          そして、新たなメモリブロックのハンドルが、hNewとして返され
          ます。
          メモリブロックの内容は、新たなメモリブロックへコピーされます
          が、小さくなった場合には、末尾部分より欠けることになります。
          また、大きくなった部分は、０クリアされません。
　　　　　ただし、デバッグモードでは常に０クリアされます。

    備考: vm_allocFix により得られたメモリブロックも変更できますが、
          新たに vm_allocタイプのメモリブロックとして確保されます。

    注意: hOld としてロック中のハンドルは使えません。
          なぜならば、メモリブロックの位置が変わり、ロック時のポイン
          タが無効になるからです。

【vm_unlock】       メモリブロックのアンロック
---------------------------------------------------------------------
    構文: vm_unlock( hand, flag );

    引数: VMHAND     hand;  ハンドル
          int        flag;  [ VM_CLEAN ] 移動時、破棄する
                              ロックしていた間、書き込みをしなかった
                            [ VM_DIRTY ] 移動時、保存する
                              ロックしていた間、書き込みをした場合

    戻値: void

    処理: vm_lock によりロックされたメモリブロックを解放し、移動可能
          にします。

    備考: vm_lock と一対一に対応させて下さい。

    注意: メモリブロックへ何等かの書き込みをしたならば、[ VM_DIRTY ]
          を指示して下さい。


=====================================================================
【vm_unlockAll】    メモリブロックの一斉アンロック
---------------------------------------------------------------------
    構文: vm_unlockAll( flag );

    引数: int        flag;  =VM_CLEAN: 移動時、破棄する
                             ロックしていた間、書き込みをしなかった
                            =VM_DIRTY: 移動時、保存する
                             ロックしていた間、書き込みをした場合

    戻値: void

    処理: vm_lock によりロックされた、すべてのメモリブロックを解放し、
          移動可能にします。

    注意: vm_lockとvm_unlock は、一対一に対応しているのが理想的です。
          よって、本関数は、出来る限り利用しないほうが良いでしょう。

【Fmemcpy】         NEAR,FARメモリに対応した memcpy()
---------------------------------------------------------------------
    構文: Fmemcpy( pDst, pSrc, uLen );

    引数: void far  *pDst;  コピー先のメモリブロックへのポインタ
          void far  *pSrc;  コピー元のメモリブロックへのポインタ
                            上記２つは、正しくプロトタイプ宣言されていれば、
                            NEAR,FARどちらでもよい。
          unsigned   uLen;  コピーバイト数

    戻値: void

    処理: メモリブロック間のコピーを行います。
          コピー元は変化しないことが保証されています。

    注意: [ pDst < pSrc ] かつ、コピー領域の一部でも重複する場合には、
          正しくコピーされません。
          Fmemmove()ならば、重複関係を判断しますが、コピー元が破壊され
          る可能性があります。


=====================================================================
【Fmemmove】        NEAR,FARメモリに対応した memmove()
---------------------------------------------------------------------
    構文: Fmemmove( pDst, pSrc, uLen );

    引数: void far  *pDst;  転送先のメモリブロックへのポインタ
          void far  *pSrc;  転送元のメモリブロックへのポインタ
                            上記２つは、正しくプロトタイプ宣言されていれば、
                            NEAR,FARどちらでもよい。
          unsigned   uLen;  転送バイト数

    戻値: void

    処理: 転送領域の重複部を判断して、メモリブロック間の転送を行います。
          重複しないことが明らかな場合は、Fmemcpy()の方が高速です。

    注意: 転送元が破壊される可能性があります。
          だから、「コピー」ではなく「転送」と言っています。

#include "vm_Dos.h"

#define  MAX_HEAP      (128 * (1024/DOS_PARAGRAPH))  /* パラグラフ単位 */
#define  PAGE_SIZE        2   /* ページサイズ (Kbyte) */

static int errHandler( iNo, zMsg )
int iNo;
char *zMsg;
{
    if( zMsg ) puts( zMsg );   /* メッセージがあれば表示する */
    
    return(0);  /* 強制終了 */
}

void main()
{
    VMHAND   vh;
    char    *pz;
    
    /* (1)初期化 */
    if( vm_init( 0, MAX_HEAP, VM_ALLSWAP, PAGE_SIZE, errHandler ) != 0 )
        exit(-1);
    
    /* (2)アロケート */
    vh = vm_alloc( 5 );
    
    printf("size=%u.\n", vm_size( vh ) );    /* size=5. */
    
    /* (3)アドレス固定  load or lock */
    pz = (char *)vm_load( vh, VM_DIRTY );  /* VM_DIRTY:更新する */
    
    strcpy( pz, "xxx" );
    vm_check( 1 );  /*** CHECK ***/
    
    /*
        strcpy( pz, "xxxxxXXX" );  /* <== もし、これを加えれば   */
        vm_check( 1 );             /* <== ここでエラーが検出される */
    */
    
    /* (4)解放 */
    vm_free( vh );
    
    /* (5)終了 */
    vm_term();
    
    exit(0);
}
