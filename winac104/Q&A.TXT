【Ｑ】
　GlobalAlloc()でも同じことができると思うのですが、何が違うのですか？
---------------------------------------------------------------------
【Ａ】
　設計方針が、かなり違います。

　Windows API における GlobalAlloc() は、MS-DOS における メモリ・ファ
ンクション同様にＯＳ直接の機能です。
　このような機能は、ＯＳの都合に合せて設計されています。つまり、プロ
グラムへの優先度は低いのです。

　例えば、MS-DOS の場合、パラグラフ(16byte)単位でしか扱えませんし、
Windows の場合は、３２バイト単位であり、かつ常にヘッダとして２４バイ
トのオーバヘッドを伴います。つまり、１バイトのブロックを確保すると実
際には５６バイト消費していることになります。
　また、共にＯＳのパフォーマンスを優先に処理するために、プログラムか
ら見ればかなり低速です。

　MS-DOS においてＣ言語には、プログラムに都合の良いように設計された
malloc() などが提供されています。
　ところが、Windows において malloc() は、単に LocalAlloc() に変換さ
れるだけで、せっかくのプロテクト・メモリが利用できません。

　そこで、プロテクトメモリに対応し、プログラムに都合の良いように設計
されたのが WinAlloc です。

　また GlobalAlloc() によって確保できるブロック（セグメント）数は、
Windows 動作中の全プログラム合せて８１９２個に制限されています。
　これも WinAlloc では、大幅に緩和することに成功し、実質無制限になっ
ています。

【Ｑ】
　MS-DOS上のプログラムで、malloc() を利用していた部分が置き換えられる
のですか？
---------------------------------------------------------------------
【Ａ】
　置き換えられます。
　特に、ミディアムやラージモデルで「ＦＡＲポインタ」として扱われてい
た場合には、_wAlloc() に置換するだけです。
