【作動環境】
---------------------------------------------------------------------
対応機種： Microsoft Windows 3.0,3.1(J) がプロテクトモード(*1)で動作
　　　　　 し、下記の対応言語処理系が動作する機種
対応ＯＳ： MS-DOS 3.3～6.0(/V), IBM DOS (J)4.0～5.0(/V)
対応言語： [A] Microsoft 6.0～7.0(A) + SDK, Quick-C/W
           [B] Borland C++ 2.0～3.1, Turbo C/W
           メモリモデル [ Small, Medium, Compact, Large ](*2)
           その他のコンパイラ、メモリモデルについては御相談下さい。

(*注釈)･･････････････････････････････････････････････････････････････
(*1) スタンダードモードまたは３８６エンハンストモードのことです。
     Windows 3.1 からは、プロテクトモードだけになりました。
(*2) Freeware Edition.では、[ Compact ]だけを提供します。

【仕様制限】
---------------------------------------------------------------------
  以下は、Professional Edition. リリースモード(*1)における、各項目毎の
仕様を列記したものです。
  全体の仕様は、最初に制限を受けた項目によって変化します。

o １つのメモリブロック(*2)の大きさ：2byteから 約65,400byte
o １つのページ(*3)の大きさ：2Kbyteから 64Kbyteまで 2Kbyte単位で可変
o １つのメモリブロックのオーバヘッド：０byte(*4)
o 総メモリブロック 数 上限：0xffffffff = 4G = 4,294,967,295個(*5)
o 総メモリブロック容量上限：0xffffffff = 4G = 4,294,967,295Byte(*5)

(*注釈)･･････････････････････････････････････････････････････････････
(*1) デバッグモードでは、各メモリブロックに４byteのチェックコードが
　　 埋めこまれます。
(*2) プロテクトメモリ上に確保されるメモリです。
     約2,000byte以下の場合に最高のパフォーマンスを発揮します。
(*3) WinAllocがＯＳ(Windows)にメモリを要求する単位です。
     WinAllocは、このページ内に多数のメモリブロックを割り当て、効果的
     に管理します。
(*4) １ページ毎に、36byte消費します。１ﾒﾓﾘﾌﾞﾛｯｸあたりのコストは僅かです。
(*5) Windows仕様により制限されます。
     Win 3.1 の 386ｴﾝﾊﾝｽﾄﾓｰﾄﾞ（i386CPU以上）ならば、4GByte,
     Win 3.0 の 386ｴﾝﾊﾝｽﾄﾓｰﾄﾞ（i386CPU以上）ならば、64MByte,
　　 ｽﾀﾝﾀﾞｰﾄﾞﾓｰﾄﾞ（i286CPU以上）ならば、16MByteです。

【関数一覧】
---------------------------------------------------------------------
_wAlloc          メモリブロックの確保     malloc同様にお使いください。
                 約５０～８０％の速度向上が期待できます。
                 戻値は、常にＦＡＲポインタ（32bit）です。
_wCheck          各種の診断をします
                 適当な箇所に挿入すれば、バグの早期発見が可能です。
_wFree           メモリブロックの解放
_wFreeAll        メモリブロックの一斉高速解放
_wInit           ＷｉｎＡｌｌｏｃ初期化   最初に必ず呼び出して下さい。
                 メモリブロックの確保が失敗した場合に呼び出される関数
                 を定義することができます。
_wRealloc        メモリブロックのサイズを変更する
_wSize           メモリブロックのサイズを取得する
_wTerm           ＷｉｎＡｌｌｏｃの終了   最後に必ず呼び出して下さい。

o ＡＮＳＩ Ｃ規格非互換関数なので、前に '_' を付けました。

【コンパイルとリンクの方法】
---------------------------------------------------------------------
# デバッグ・モード
- - - - - - - - - -
　開発段階に利用するモードです。
  各種のチェック機能が埋めこまれ、バグを感知したときに警告を発します。

（チェック機能概要）

o オーバーライト・チェック
　  メモリブロックへのオーバーライト（不正な書き込み）を適時チェックし
　ます。
　  また、_wCheck()により、任意の箇所でチェックさせることもできます。
　  たとえば、全てのオーバーライトの可能性がある行の直後に _wCheck()
　を挿入すれば、早期に発見することができます。
　　Ｃのポインタは、Ｃ言語の特徴であり大変な効果をもたらしてくれるので
　すが、オーバーライトに起因するバグの発生率を高めています。このような
　バグは、時間差発生するために発見が困難です。
  　オーバーライト・チェックは、このような問題を解決します。

o メモリリーク・チェック
    _wTerm()により、メモリブロックのリーク（解放忘れ）をチェックします。
　  また、_wCheck(1)により、任意の箇所でチェックさせることもできます。
  　ＤＯＳプログラムは、シングルプロセスを前提に開発されているために、
  マルチプロセスにおけるリソースの概念が欠けています。
  　メモリブロックは、貴重なリソースです。使い終われば確実に返却するこ
  とを心掛けてください。そうすれば、思いがけないバグの発生を防ぐことに
  もなります。
  　ＷｉｎＡｌｌｏｃは、どのような状態であっても _wTerm()によりすべての
  メモリブロックを確実に解放してくれます。しかし、メモリリーク・チェッ
  クにより完成度の高いプログラムに仕上げて下さい。

o ＷｉｎＡｌｌｏｃセルフ・チェック
　　ＷｉｎＡｌｌｏｃ自身が利用しているメモリ周辺をチェックします。
　　また、ＷｉｎＡｌｌｏｃ関数の引数や内部処理のチェックを厳密に行うこ
  とによりアプリケーションからの不正な利用を早期に発見します。

（コンパイル方法）
　ＷｉｎＡｌｌｏｃ関数を利用したソースファイルを、/D_AP_DEBUG オプショ
ンを付けて、コンパイルして下さい。
  (例) Compactモデルの場合
       MSC: cl /c /DWINVER=0x0300 /AC /W3 /Zp /G2w /D_AP_DEBUG xxx.c
        BC: bcc -c -mc -v -WE -D_AP_DEBUG  xxx.c

（リンク方法）
　コンパイラとモデルに対応したライブラリをリンクして下さい。
  (例) Amatur Edition. Compactモデルの場合
       MSC: link /NOD /ONERROR:NOEXE /ST:8000 xxx.obj,,nul, CA_WAC.lib ;
        BC: tlink /c /d /L$(CC)\lib xxx.obj,,nul, WAC_CA.lib 


# リリース・モード
- - - - - - - - - -
  デバック・モードで埋めこまれる機能を除き、最高のパフォーマンスを提供
するモードです。
　ソースリストの変更は、一切不要です。

（コンパイル方法）
　ＷｉｎＡｌｌｏｃ関数を利用したソースファイルを、/D_AP_DEBUG オプショ
ンを外して、コンパイルして下さい。
  （assert()を利用している場合は、/DNDEBUG オプションを付けます。）
  (例) Compactモデルの場合
       MSC: cl /c /DWINVER=0x0300 /AC /W3 /Zp /G2w /Otelg /Gs /DNDEBUG xxx.c
        BC: bcc -c -mc -v -WE -O2 -DNDEBUG  xxx.c

（リンク方法）
  デバック・モードと同様に、コンパイラとモデルに対応したライブラリを
リンクして下さい。
  (例) Amatur Edition. Compactモデルの場合
       MSC: link /NOD /ONERROR:NOEXE /ST:8000 xxx.obj,,nul, CA_WAC.lib ;
        BC: tlink /c /d /L$(CC)\lib xxx.obj,,nul, WAC_CA.lib
